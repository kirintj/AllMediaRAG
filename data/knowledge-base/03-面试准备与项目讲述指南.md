## 一、Agent 面试三层考察体系

### 层 1：概念理解（筛选层）

区分"调包侠"和有源码级理解的候选人。

| 问题 | 表面回答 | 深层回答方向 |
|------|---------|-------------|
| Agent vs Chatbot | "能调工具" | Agent Loop 包含内层循环，检测 tool_calls 后继续执行并回调 LLM，本质是 while 循环 |
| Agent 为何不稳定 | 归因于幻觉 | 多轮工具调用构成串行决策链，上下文膨胀后早期信息被压缩/截断 |
| Memory 设计 | 仅提向量数据库 | 三层架构：MEMORY.md 跨 Session 持久化、assemble() 组装最优上下文、compact() 压缩早期对话 |

### 层 2：工程经验（核心层）

面试官通过追问实现细节判断是读过源码还是仅看教程。

**关键问答：**

**执行模型**：EventStream 模式下，Agent Loop 作为 AsyncGenerator 流式发射结构化事件序列（agent_start → turn_start → message_update → tool_execution → turn_end → agent_end）。上层 UI 消费 EventStream 做渲染，逻辑与 UI 完全解耦。

**工具执行方式**：默认并行。LLM 一次返回多个 tool_calls 时用 Promise.all 并行执行，延迟从 O(n) 降到 O(1)。

**上下文溢出处理**：Context Engine 双策略——compact() 对早期对话生成 LLM 摘要；assemble() 按优先级裁剪：系统指令 > 持久化记忆 > 压缩摘要 > 近期对话。

**MCP 协议**：工具作为独立进程通过 JSON-RPC over stdio/HTTP 与 Agent 通信。实现语言无关、进程隔离、社区可独立开发共享。

### 层 3：系统设计（高级层）

**设计支持 10,000 文件的 Coding Agent**：
- 不能全量塞入上下文——用 Read 工具的 offset/limit 按需读取
- 文件发现用 grep/find 而非全量遍历
- 大规模重构用 Worktree 隔离 + SubAgent 并行

**多用户安全隔离**：
- Session 级别隔离（独立 Context Engine 实例）
- 文件系统级别隔离（Docker 沙箱）
- 工具权限隔离
- 秘钥隔离

## 二、项目经历讲述框架（STAR 格式）

### 模板

- **Situation**：需要编程辅助 Agent，主流框架太重且不可控
- **Task**：基于某架构改造个人 Coding Agent
- **Action**：接入多 Provider，添加持久化记忆、外部接入、构建 Eval 测试集
- **Result**：任务完成率提升，上下文压缩使单次会话工具调用轮次大幅增加

### 三个核心判断论证

面试官想听的不是用了什么技术，而是做了什么判断：

1. **框架选择依据**：为什么选/不选 LangChain？——隐式处理太多，出问题无法精确定位
2. **执行模式选择依据**：EventStream 模式支持实时反馈和可观测性
3. **存储选择依据**：MEMORY.md 文件存储——人类可读可编辑、Git 可追踪、零依赖

## 三、Eval 量化评估体系

> 面试中能说出具体 pass rate 数字的候选人极少，这是**显著差异化优势**。

### 四个评估维度
1. 读取分析
2. 单文件修改
3. 多文件重构
4. 测试编写

### 面试话术要点
1. 先说初始 pass rate
2. 再说优化了什么策略（上下文压缩、工具结果截断）
3. 给出提升后数字
4. 分析主要失败 case 及后续改进方向

## 四、进阶面试题（源码级）

### OpenClaw vs Claude Code 的 Compaction 区别
- OpenClaw：压缩时做标识符保留（文件路径、函数名、行号原样保留）+ 质量检查点
- Claude Code：直接用 LLM 摘要，无验证步骤

### Dreaming 系统
解决记忆质量随时间退化。三阶段定时合成——扫描候选记忆、合并相似主题、跨主题关联。仅 grounded snippets 可被提升，防止幻觉记忆。

### GBrain "确定性操作优先于 LLM 判断"原则
LLM 调用三个问题：成本高、不确定性、延迟高。实体抽取用正则，关系链接用模式匹配——确定性、免费、毫秒级。仅在必须推理时才调用 LLM。

## 五、面试准备清单

1. GitHub 上有可运行的项目（有个人改动）
2. README 包含改动说明和架构图
3. 能在 1 分钟内讲解 Agent Loop 的 EventStream 模式
4. 能回答 Context Engine 的 assemble/compact 工作机制
5. 能解释框架选择的判断依据
6. 有 Eval 量化数字（pass rate + 改进前后对比）
7. 能画出项目包结构和数据流图

## 六、最核心原则

> **把 Agent 真正跑起来并日常使用。**

面试中被追问的任何细节——上下文溢出处理、工具出错处理、多文件任务拆解——如果有真实使用体感，自然能给出有判断力的回答。这些体感无法靠背诵获得，面试官能够分辨。
