# 1. 架构选型

覆盖公司：腾讯、蚂蚁、字节、阿里、快手、美团等

## Q1：你用 ReAct 还是 Plan-and-Execute？为什么？

**来源：** 腾讯终面；蚂蚁二面；字节二面

**新手答：** 看情况，复杂用 ReAct，简单用 Plan。

**高手答：**
- ReAct 核心是推理与行动交替循环，每一步基于上一步真实反馈，天然适应不确定性
- Plan-and-Execute 是规划与执行分离，全局最优、可预测，但对中间变化适应性弱
- 选择维度是**任务不确定性**：流程固定的任务用 Plan-and-Execute 省成本；开放任务用 ReAct
- 核心技巧是在 Plan 的每个步骤里嵌入 ReAct 式检查点

**考察点：** 不是考"知不知道这两个东西"，而是"在实际系统里怎么选、怎么用"

---

## Q2：CoT 和 ReAct 的核心区别是什么？

**来源：** 淘天二面

**高手答：**
| 维度 | CoT | ReAct |
|------|-----|-------|
| 本质 | 纯推理链 | 推理+行动交替 |
| 信息来源 | 仅靠模型内部知识 | 可通过工具获取外部信息 |
| 典型输出 | 思考过程→最终答案 | Thought→Action→Observation→循环 |

关键区别：CoT 是**信息闭环**，ReAct 是**信息开环**。判断标准：回答问题需不需要模型目前不知道的信息？

---

## Q3：Plan-and-Execute 架构里，Planner 和 Executor 之间是如何通信的？

**来源：** 字节二面

**高手答：**
- Planner 输出结构化执行计划（JSON 格式，含 step_id、action、params、depends_on）
- 三种通信模式：一次性计划、迭代式重规划（最常用）、事件驱动

---

## Q4：Tree of Thoughts (ToT) 在线上系统里能用吗？

**来源：** 腾讯终面

**高手答：**
- 重度 ToT 线上不能用，但轻量化版本是杀手锏
- 实际应用：并行生成3条不同风格回复草稿，再用轻量评判模型选出最合适的一条
- 本质是束搜索（Beam Search），成本是单次生成的3倍，但关键场景 ROI 很高

---

## Q5：Agent 的架构设计？从系统角度来拆分

**来源：** 阿里一面

**高手答：** 核心拆成四层：
1. **任务入口层**：接收用户问题和上下文
2. **决策层**：意图识别、任务拆解、规划、工具选择
3. **执行层**：调工具、查知识库、访问服务
4. **记忆与状态层**：维护多轮上下文、历史执行结果
5. **校验层**：参数合法性校验、结果一致性校验

---

## Q6：Agent 在学术上由哪些部分组成？

**来源：** 字节一面

**高手答：** 按学术框架（Lilian Weng 综述）：
- **LLM（大脑）**：核心推理引擎
- **Planning（规划）**：任务分解、自我反思（CoT、ToT、ReAct）
- **Memory（记忆）**：短期记忆和长期记忆
- **Tool Use（工具使用）**：调用外部 API、搜索引擎等

---

## Q7：了解过 Agent 的设计范式吗？

**来源：** 字节一面；淘宝闪购一面

**高手答：** 四种主流范式：
1. **ReAct**：灵活适合开放性任务，token 消耗大
2. **Plan-and-Execute**：适合流程固定的任务，省 token 但不灵活
3. **反思范式（Reflexion）**：适合质量要求高的场景
4. **多 Agent 协作**：适合需要多视角的复杂任务

---

## Q8：如何避免规划器路径震荡？

**来源：** 腾讯二面

**高手答：**
- 把规划分成"全局计划"和"局部调整"两层
- 加"重规划阈值"：只有关键前提失效、连续失败或用户目标变化时才重新规划

---

## Q9：如何把模型放进一个强约束工作流里？

**来源：** 腾讯二面

**高手答：** 核心原则："系统控流程，模型控局部智能"——模型只负责局部判断和内容生成，流程推进由外部状态机控制。

---

## Q10：什么时候该做 Agent？和 Workflow 的边界在哪？

**来源：** Agent 开发面试 30 题

**高手答：** 判断标准是**决策路径是否在设计时可穷举**：
- 所有分支可预知 → Workflow
- 分支可穷举但语言理解复杂 → Prompt 链
- 分支不可穷举，需运行时决策 → Agent

---

## Q11：为什么很多团队做到最后是"Workflow + Agent 节点"的混合架构？

**高手答：** 80%步骤是确定性的，20%需要智能判断。确定性环节用 Workflow，不确定性环节用 Agent。

---

## Q12：Agent 系统里，模型和系统代码的职责边界怎么划？

**高手答：**
- 模型负责：意图识别、参数抽取、方案选择、内容生成
- 系统代码负责：流程控制、参数校验、权限管控、状态持久化、安全兜底
- 验证标准：出错后果严重且不可接受 → 系统代码负责

---

## Q13：如果面试官说"Agent 本质上就是套壳调用工具"，你怎么反驳？

**高手答：** Agent 有三个"套壳"做不到的能力：
1. **动态规划**：决策链在设计时不可穷举
2. **自我修正**：失败后分析原因、换工具重试
3. **上下文推理**：综合多轮对话、用户画像做决策

---

## Q14：生产级 Agent 的执行循环包含哪些阶段？

**高手答：** 七阶段循环：输入解析→上下文组装→规划/决策→参数校验→工具执行→结果校验→状态更新。学术三步 vs 生产七步，多出来的四步全是工程防线。

---

## Q15：现在的 Agent 架构和之前有什么本质不同？

**来源：** 蚂蚁二面

**高手答：** 从"一次性全量加载"到"渐进式按需披露"的范式转变。按需加载工具、上下文随阶段演化、能力逐级升级。

---

## Q16：Skill、MCP、Rule 三者有什么区别？

**来源：** 蚂蚁一面

**高手答：**
| 概念 | 本质 | 解决什么 | 类比 |
|------|------|----------|------|
| Rule | 行为约束规则 | 能做什么、不能做什么 | 公司制度 |
| Skill | 可复用的能力模块 | 怎么做某类特定任务 | 员工专业技能 |
| MCP | 工具连接协议 | 怎么接入外部工具和数据 | USB 接口标准 |

---

## Q17：微服务怎么接入一个 Agent 系统？

**来源：** 蚂蚁一面

**高手答：** 三个层面：服务发现与注册、协议适配（REST/gRPC → Tool Schema）、治理（鉴权、限流、熔断、可观测）

---

## Q18：如何保证规划 Agent plan 的结果正确？

**高手答：** 三个阶段：事前约束（Structured Output）→ 事中校验（Critic Agent）→ 事后修正（Self-Reflection）

---

## Q19：Human-in-the-Loop 如何用 SSE 实现？

**高手答：** LangGraph 的 `interrupt_before` 暂停 → 用户修改 → `graph.update_state()` 注入 → `graph.stream(None, config)` 继续

---

## Q20：模型和 Agent 的区别到底是什么？

**来源：** 字节实习一面

**高手答：** 模型是一个**函数**（输入→输出），Agent 是一个**系统**（目标→自主多步执行）。区分关键在于**循环**——调一次工具是增强版模型，能自主决定多步执行才是 Agent。

---

包括：LangChain vs LangGraph 区别、Self-Reflection 机制、NL→执行的保障、多角色客服RAG vs Skill选择、监控日志Agent分析、Skill vs Workflow区别、DAG vs 含循环图、基于RL的Agent vs Prompt-based Agent 等。

**答题模式总结：** 架构选型题的高分回答有固定结构：①给出明确选择维度 ②用具体业务场景说明 ③说出混合方案或工程化降级技巧 ④点一句代价和适用边界

# 2. 工具管理

覆盖公司：腾讯、蚂蚁、字节、阿里、快手、高德等

## Q1：模型也瞎传参数怎么办？

**来源：** 腾讯终面

**高手答：** 三层防线——Schema 里写"负面描述"→ 输出后做 Pydantic 硬校验 → 关键参数业务兜底（先调用校验接口确认）

---

## Q2：工具库有上百个工具，怎么让模型快速选对？

**来源：** 腾讯终面

**高手答：** 构建轻量级工具路由层：FastText 提取意图 → 工具向量库语义检索 top 5 → 7B 小模型精排序 → 只把 top 2 工具完整 schema 交给大模型。分层路由从100+缩到3。

---

## Q3：MCP Server 是怎么构建的？

**来源：** 字节实习二面

**高手答：** MCP 是三角色架构（Host/Client/Server）+ 能力协商 + 标准化通信的完整协议。关键步骤：定义 Tool Schema → 实现 Handler → 选择传输方式（stdio/HTTP+SSE）→ 注册与发现。

---

## Q4：Function Calling 的本质价值是什么？

**高手答：** FC 解决的主要是**系统约束问题**——把"模型想调工具"从自由文本变成结构化协议，解决输出格式不可靠、调用时机不可控、参数类型无约束三个问题。

---

## Q5：工具多导致 token 数过多怎么解决？

**来源：** 字节实习二面

**高手答：** 动态工具加载 → 工具描述压缩（200字→50字）→ 分层工具组织（先选大类再选具体）→ 工具向量检索

---

## Q6-Q22 更多题目

包括：多工具调度策略、Mock实现、工具返回语义不完整时的中间层设计、MCP完整调用过程、LLM如何从意图匹配到工具参数、多轮工具调用额外挑战、推理模型为何不支持工具调用、开源模型FC能力提升等。

**答题模式总结：** 工具管理题的核心是**防御性思维**——不信任模型输出、分层防御、大规模工具管理用检索思路。

# 3. 容错与鲁棒性

覆盖公司：腾讯、蚂蚁、字节、阿里、快手等

## Q1：调支付接口超时了，Agent 怎么处理？

**来源：** 腾讯终面

**高手答：** 错误分类处理：网络超时/5xx走指数退避重试（最多2次）；4xx触发"参数诊断"子流程；核心路径工具失败时启动备选通道。

---

## Q2：Agent 的决策出错了怎么防范？

**来源：** 腾讯终面

**高手答：** Dry-run模式 → 操作分级+多人确认 → 完整溯源日志 → 权限隔离（最小权限原则）

---

## Q3：Agent 如何减少幻觉？

**来源：** 字节一面

**高手答：** 三阶段多层防线——生成前（Prompt约束+RAG注入+上下文精简）、生成中（Structured Output+引用溯源）、生成后（事实校验+一致性检测+人工兜底）

---

## Q4：怎么限制 Agent 的思考深度避免无限循环？

**高手答：** 三层限制——硬性上限（全局步数15步、单工具连续失败2次禁用）→ 行为检测（重复检测、进度检测、目标漂移检测）→ 预算感知（注入当前资源消耗状态让模型主动收敛）

---

## Q5：Prompt 注入攻击如何防御？

**来源：** 快手一面

**高手答：** 区分直接注入和间接注入，四层防御：输入过滤 → Prompt加固 → 上下文隔离 → 输出检测

---

## Q6-Q23 更多题目

包括：失败恢复机制、资源紧张排队机制、shell命令安全、文件系统权限管理、工具调用安全控制、RAG无法彻底解决幻觉的原因、Self-Reflection机制、Reflection连续失败降级、金融系统Agent设计、安全护栏设计、NL2SQL安全防护等。

**答题模式总结：** 容错题核心是**分类处理+层层兜底**——先对错误分类、每类有明确处理链路、写操作有防护、所有决策有日志。

# 4. 记忆与上下文

覆盖公司：腾讯、字节、蚂蚁、阿里、快手、美团、高德等

## Q1：长上下文里怎么让 Agent 不忘记关键信息？

**来源：** 腾讯终面

**高手答：** 三段式记忆——滚动窗口记忆（最近3-5轮原样保留）、关键实体记忆（NER抽取存入类知识图谱结构）、周期性摘要记忆（每10轮生成结构化摘要）。查询时三段信息同时召回按权重融合。

---

## Q2：用户说"按老样子帮我订一下"怎么处理？

**来源：** 腾讯终面

**高手答：** 先"猜"再"问"——立刻检索历史订单，找出最近/频次最高/标记"喜欢"的候选，把1-3个选项抛给用户确认。

---

## Q3：上下文窗口不够用怎么办？

**高手答：** 四层方案——早期对话压缩成结构化摘要、大任务拆子任务中间结果通过数据库传递、中间结果落库上下文只留状态说明、按需回溯建索引。

---

## Q4：讲一下 Agent 中的"长短期记忆"

**高手答：** 类比人类认知分三层——感知记忆（当前输入+最近1-2轮）、短期记忆（上下文窗口内全部历史）、长期记忆（外部存储跨会话持久）。进阶补充"工作记忆"——多步任务执行时的中间状态。

---

## Q5：Lost in the Middle 问题是什么？

**高手答：** 四个层面——信息布局优化（最重要放开头或结尾）、检索阶段优化（控制数量+Rerank）、上下文压缩、结构化标记。本质是Attention机制分布不均匀。

---

## Q6：设计三层记忆机制

**高手答：** 工作记忆（最近3-5轮原始对话，零压缩，内存/Redis）→ 短期记忆（会话级结构化摘要，中度压缩，数据库）→ 长期记忆（跨会话向量化知识库，高度压缩，向量库+KV）

---

## Q7-Q45 更多题目

包括：多Agent上下文污染防治、上下文工程核心工作、Checkpoint存储选型、Claude Code记忆架构、MemGPT前沿、会话记忆实现、话题切换记忆设计、记忆冲突解决、压缩丢失工具历史的解法等。

**答题模式总结：** 记忆题核心是**多层次+产品思维**——Memory是多层系统、存什么/怎么查/怎么融合都要说清、模糊需求"先猜再问"。

# 5. 评估与全局观

覆盖公司：腾讯、蚂蚁、字节、快手、美团等

## Q1：如何量化评估一个上线的 Agent？

**来源：** 腾讯终面

**高手答：** 三维看板——效能维度（完成率、步数、耗时、Token成本）、质量维度（准确率、满意度、一次解决率）、鲁棒性维度（异常处理成功率、自修复率）。关键是每次失败必须归因到具体模块。

---

## Q2：当前阻碍 Agent 大规模落地的最大挑战？

**高手答：** 核心是可控性与能力的权衡困境。实践方案：核心逻辑层用状态机保证主干，在安全沙盒内给模型最大自由。

---

## Q3：怎么给 Agent 建立评测体系？

**高手答：** 四个维度：效果（成功率、准确率）、效率（步数、token、延迟）、鲁棒性（异常恢复率）、过程质量（工具选择正确率、无效步数占比）。评测集：基础60%+边界20%+对抗10%+回归10%。

---

包括：Agent线上最难监控指标、记忆系统评估、AI工具最大帮助、Agent框架改进方向、RAG系统评测方法、Ragas评测框架、Vibe Coding理解、AB测试设计、AI对算法工程师角色影响等。

---

## Q3：单 Agent 还是多 Agent？

**高手答：** 三个判断维度：能力边界是否清晰、上下文是否容易污染、是否存在天然并行。

# 7. 工程化踩坑

## Q1：开发 Agent 时踩过什么坑？

# 9. RAG 与检索系统

## Q1：RAG 的检索如何实现？

**高手答：** 离线（清洗→切片→去重→embedding→入库）；在线（query编码→向量召回→BM25混合→rerank重排→拼接证据给LLM）

---

## Q2：召回了很多相互矛盾的文档怎么处理？

**来源：** 腾讯二面

**高手答：** 先做证据归一化和冲突检测：按来源/时间/可信度分组 → 抽取同一字段不同取值判断冲突类型 → 冲突消解。Agent应做证据调解器。

---

## Q3：RAG与模型微调相比？

**高手答：** RAG是"外挂知识"——改文档即生效、可追溯；Fine-tuning是"内化知识"——固化风格/格式。最优解常是混合方案：Fine-tuning学会"怎么说"，RAG注入"说什么"。

# 10. 训练、数据与模型优化

## Q1：Agent 工具调用怎么训练？

**高手答：** 训练集需覆盖正样本、负样本、复杂样本。数据来源：人工标注、线上日志回放、规则合成、模型自举。关键是负样本和边界样本。

---

## Q2：DPO、PPO、GRPO 的区别？

**高手答：**
- PPO：在线RL，需Reward Model+Critic共4个模型，效果天花板高但复杂
- DPO：离线偏好优化，1个模型像SFT一样简单但无法在线探索
- GRPO：在线组相对优化，每prompt采样一组用组内排名做奖励，无Critic

---

# 15. 概念考察

## Q1：Harness Engineering 是什么？

**高手答：** 用工程化手段约束和增强 Agent 行为的系统方法论。三层：约束层（Rules/安全护栏）、增强层（Skills/动态工具注册）、验证层（评测/日志采集）。

---

## Q2：Prompt Engineering、Context Engineering、Harness Engineering 三者区别？

**高手答：**
| 维度 | Prompt Engineering | Context Engineering | Harness Engineering |
|------|---|---|---|
| 核心关注 | 怎么写指令 | 怎么给模型恰好的信息 | 怎么用工程体系约束和增强模型 |
| 解决的问题 | 模型不知道该做什么 | 模型缺少做事需要的信息 | 模型做事时缺少约束和保障 |

---

## Q3：Agent 的发展路线？

**高手答：** 四阶段：Prompt Chain（2023）→ Autonomous Agent（2024上）→ Workflow+Agent混合（2024下）→ Harness Engineering（2025-2026）

---

## Q4：MCP vs Function Calling vs Skills？

**高手答：** 三者扩展不同层面：FC是模型输出格式规范，MCP是工具的标准连接协议，Skills是可复用的知识+指令单元。类比：FC=会说话，MCP=有电话网络，Skills=有操作手册。

---

## Q5：Agent 和 Siri 的核心差别？

**高手答：** 核心在架构范式：Siri是管道式（意图识别→槽位填充→固定API），Agent是闭环架构（理解目标→自主规划→动态选工具→反思调整）

---
